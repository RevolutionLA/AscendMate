# 01 产品需求文档（PRD）

## 1. 产品背景

### 1.1 现状分析

AscendMate 目前以 VitePress 静态文档站的形式托管在 GitHub Pages 上，提供了完善的昇腾智算生态技术资料，涵盖：

- 学习路径（六阶段 AI 入行体系）
- 环境搭建（7 步从裸机到可跑代码）
- 模型训练（LLaMA-Factory 微调、MindSpeed 预训练）
- 模型推理（MindIE、vLLM-Ascend、SGLang、Dify）
- 算子开发（Ascend C、Triton、CATLASS）
- 运维监控（Prometheus + Grafana NPU 大屏）
- 场景价值（金融、医疗、政务、制造行业方案）
- 算力运营管理（利用率、调度、成本核算）
- 资源导航与 FAQ

现有平台为**桌面端优先**，在手机浏览器上阅读体验不佳：导航拥挤、代码块溢出、全文搜索入口不便。

### 1.2 机会

- 昇腾开发者群体日益增长，移动端碎片时间学习需求旺盛
- 运维和交付人员经常在工作现场需要快速查资料，手机是最佳终端
- HarmonyOS NEXT（纯血鸿蒙）生态日趋成熟，原生 APP 体验远优于 Web 壳
- 鸿蒙的元服务、Widget、多端协同能力可创造区别于普通 APP 的独特体验

## 2. 产品目标

构建一款**鸿蒙原生 APP**，将 AscendMate 资料栈**全量内置到手机端**，做到**安装即用、永久离线可用**，并利用鸿蒙特性提供超越 Web 浏览的用户体验。

### 2.1 核心产品原则（三大支柱）

| 支柱 | 原则 | 说明 |
|------|------|------|
| **① 全本地化** | 永不联网，内容全内置 | 所有文章、图片、索引打包进 APP；无网络权限、无加载等待、无空白页；离线场景（机房、地铁、出差）体验完全一致 |
| **② 消除陌生感** | 零学习成本，一看就会 | 首次启动引导、与网页一致的命名与结构、内嵌示例搜索词、渐进式功能揭示，让新用户 30 秒内完成第一次有意义的操作 |
| **③ 精致高级** | UI 丝滑、视觉考究 | 系统性动效设计、毛玻璃质感、品牌化视觉语言，让用户在翻页、滚动、搜索的每一帧都感到"顺畅、漂亮、值得反复打开" |

### 核心目标

| 维度 | 目标 |
|------|------|
| **信息获取** | 用户在手机上可快速浏览、搜索、收藏昇腾全栈技术资料 |
| **碎片化学习** | 支持学习路径跟踪、阅读进度保存，方便通勤/间隙时间学习 |
| **现场运维辅助** | 运维人员可在现场快速查阅 FAQ、命令手册、运维 SOP |
| **沉浸阅读** | 代码块适配手机屏幕展示优化，Markdown 渲染精致 |
| **离线可靠** | **100% 离线可用**：全部内容来自本地包，无任何网络依赖 |
| **零门槛上手** | 新用户首次打开 30 秒内完成首次搜索/阅读，无需任何引导成本 |
| **UI 高级感** | 动效系统化、视觉质感专业化，达到华为系 APP 水准 |
| **鸿蒙原生** | 充分利用元服务、Widget、多端协同等鸿蒙特性 |

### 非目标

- 不做昇腾服务器直接管理功能（保留给 Ascend Assistant Skill）
- 不做实时 NPU 监控仪表盘（保留给 Grafana 移动端）
- **不做任何在线内容获取**：不联网、不拉取远程数据、内容全部随安装包分发
- 不做账号体系强制绑定：华为账号仅作可选的本地数据跨设备迁移，未登录也可用全部功能

## 5. 数据需求与内容源

### 5.1 核心原则：**全本地、零联网**

本 APP 是**纯离线应用**，不申请任何网络权限，不与任何服务器通信。所有内容在应用构建阶段（CI）打包进安装包，用户安装后即可使用全部功能。

```
内容生产链路（开发侧）：
GitHub 仓库 docs/*.md
      │  CI 构建脚本（GitHub Actions）
      ▼
内容管线：markdown 预处理 → 元数据抽取 → 搜索索引生成 → 图片资源收集
      ▼
打包进 HAP 安装包的 rawfile/ 资源目录
      ▼
用户安装 APP → 全部内容已就绪 → 无需联网、无需等待
```

| 数据项 | 来源 | 分发方式 |
|--------|------|----------|
| 文档内容 | GitHub 仓库 `docs/` 目录 | 构建时打包进 rawfile，随版本发布 |
| 目录结构 | VitePress 侧边栏配置 | 构建时生成 JSON，打包内置 |
| 搜索索引 | 构建时预生成倒排索引 | 打包内置，本地毫秒级检索 |
| 图片资源 | GitHub 仓库 `docs/public/` 目录 | 构建时转码压缩，打包内置 |
| 文档更新 | 上游仓库内容变更 | 通过 APP 版本更新发布 |

> **为何选择全本地？** ① 技术资料阅读是"低频、长尾、弱实时"场景，无需在线；② 运维人员常处于机房/弱网环境，离线可靠性是刚需；③ 去除网络依赖可大幅降低启动时延、权限敏感性与功耗，提升可用性。

### 5.2 本地数据

| 数据项 | 存储方式 | 说明 |
|--------|----------|------|
| 收藏夹 | 本地数据库（ArkData RDB） | 支持自定义文件夹 |
| 阅读进度 | 本地数据库 | 按文章记录阅读位置 |
| 搜索历史 | 本地数据库 | 最近 50 条 |
| 用户偏好 | Preferences | 字体大小、主题、语言、引导完成状态 |
| 学习进度 | 本地数据库 | 阶段/章节完成状态 |
